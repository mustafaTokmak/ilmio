PROJECT CONTEXT (read fully before starting)
OfferAd is a project by a software engineer in San Francisco. Idea: when AI agents shop for people, a seller's "ad" becomes a concrete offer made to the buyer's agent at the moment of decision: a labeled concession (discount, free or express shipping, free add-on, easy returns, delivery guarantee, bulk tier, credit on the next order), with the seller's limits (floor price, approved concessions, budget) enforced in code, never in a prompt. Existing demo: a Cloudflare Worker "arena" where a buyer agent and a seller agent bargain and a code referee enforces both sides' limits, plus a remote MCP connector (tools: search_offers, make_offer, accept, walk_away) that Grok Bot can use.

WHAT THE OWNER WANTS NOW
A Shopify app version. A merchant installs it. When a buyer's personal AI agent shops that store (the new acting consumer agents: Muse from Meta, Dots from OpenAI, Grok Bot from xAI; also browser agents and ChatGPT or Gemini style assistants), the app should (1) show the price, (2) learn what the agent's user wants (priority: price, speed, returns, bundle and so on), (3) accept a competing offer LINK from the buyer's agent as proof of a better deal elsewhere and verify it itself, and (4) answer with a better offer or a different kind of offer, not only a discount, that then really applies in the Shopify checkout.
The owner's instruction: keep going until a workaround is found. Do not conclude "impossible"; if the official route is closed, find the cracks and the honest limits of each.

The full live tool schemas are in /Users/mustafatokmak/.herdr-projects/offerad/threads/t-0006/work/docs/tools-list.json.
3. Agent to store inputs in the live schema: line items, buyer contact, discounts.codes (cart and checkout), context.intent (free text), context.eligibility (reverse-domain claims such as com.example.loyalty_gold), attribution and UTM fields, fulfillment, payment.
4. Store to agent outputs: prices, totals, discounts.applied (title, amount, automatic or code, provisional, eligibility), messages[] (type, code, content, path, severity), continue_url, links.
5. UCP Discount extension: agents submit codes; rejected codes come back as warnings with codes like discount_code_user_ineligible; automatic discounts are shown; "eligibility claims" can trigger provisional discounts that must be verified before completion. UCP has NO offer, counter-offer or price-negotiation message; "negotiation" there means capability matching. A draft "ask" capability (dev.ucp.common.ask) answers natural-language questions but MUST NOT apply discounts or change state.
6. UCP lets any vendor define extensions under its own reverse-domain namespace (com.vendor.*), including "Actions" (outstanding work the agent must process), but an extension only activates if BOTH the business profile and the agent profile declare it. Shopify generates the store's profile.
7. Shopify Discount Function API (any plan, public apps): inputs include cart lines, cart attributes, line attributes, buyer identity and customer (tags, metafields), entered discount codes, discount metafield config. One function can discount products, the order and shipping together; at most 25 active per store. Network access (fetch target) is only for custom apps on enterprise stores. context.intent and context.eligibility were NOT found among the function inputs.
8. Apps can create discount codes through the Admin GraphQL API (write_discounts scope). Cart permalinks accept ?discount=CODE and attributes[key]=value. The Cart and Checkout MCP tools have no cart-attributes field.
9. Checkout WebMCP: browser agents can read and update the checkout open in the tab, submit discount codes, pick a saved Shop Pay card, and complete only after buyer confirmation; it does not cover app-defined checkout UI extensions. Storefront WebMCP tools (search_catalog, browse_store, get_product, show_variant, get_cart, update_cart, cancel_cart, proceed_to_checkout, manage_orders, search_shop_policies_and_faqs) are registered by Shopify on every Liquid storefront; agent support for WebMCP is limited to Chromium browsers.
10. Server agents can call complete_checkout only with a token granted that permission; otherwise the buyer finishes at continue_url.
11. Reported by press, not verified by us: Meta and Sierra announced a "Personal Agent Protocol" on 6 Oct 2026 (spec due later in October); Google runs a "Direct Offers" pilot in AI Mode; Stripe's agentic commerce suite tags orders with the originating agent and has a promotion feed.

WORKAROUND IDEAS ALREADY ON THE TABLE (improve them, kill them, or add better ones)
A. Offer token = single-use discount code. The app runs its own seller-agent endpoint (MCP or HTTP, possibly on the store's own domain through a Shopify app proxy). The buyer agent states its priority and/or a competing-offer URL; the seller agent verifies the URL itself, applies the merchant's limits in code, and returns a code plus a cart permalink. The agent submits the code through Shopify's documented discounts.codes field. A Discount Function keyed to the code can combine product, order and shipping effects; a free gift is a line the link adds and the function zeroes.
B. Discovery of that endpoint: (i) an extra WebMCP tool registered on the storefront by the app's theme app embed script; (ii) text in product descriptions, metafields, policies or FAQ that Shopify's own catalog and FAQ tools return to agents; (iii) the title of an automatic discount, which appears in discounts.applied on every cart an agent reads; (iv) JSON-LD, llms.txt or well-known files; (v) one cross-store OfferAd connector listed in the agent platforms' connector directories (Grok connectors, ChatGPT apps, Claude connectors), so the BUYER's agent already has the tool and any store with the app is reachable through it.
C. Offer menu carried by codes: the store publishes a few conditional offers; the agent picks one by submitting its code; rejection messages tell it what to change.
D. context.eligibility claims as the trigger for provisional discounts.
E. A custom UCP extension (com.offerad.*) with Actions.
F. Draft orders or invoice URLs for a negotiated price.
Known doubt: A to C need a buyer agent to call or trust something it was not told about, and agents are trained to distrust instructions found in web content.
