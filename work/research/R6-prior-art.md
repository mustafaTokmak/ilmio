## 0. Headline findings

1. **Somebody is already doing the core of idea A + B(v).** Flux (withflux.co.uk, FLUXAI GROUP HOLDINGS LTD, UK, founder Ben Ouattara) is a Shopify App Store app (launched 5-8 Jun 2026) that negotiates with buyer AI agents: a cross-store "Flux" ChatGPT app and a Claude MCP connector, OAuth identity ("Flux ID"), a vendor-namespaced UCP profile (`com.withflux.negotiate`), server-enforced floors, and a single-use Shopify discount code plus checkout link as the handoff. It is price-only (percentage discount on one product). It does not take a competing-offer link, does not offer non-price concessions, and does not live on the store's own agent surface. Details in section 1.2.
2. **Every human-facing negotiation app on Shopify lands the deal in checkout one of three ways:** (a) a unique single-use discount code (Nibble on WooCommerce, Flux, Fasel, PricePitch, Lury, Fluxley, Bargain Buddy, Hagl, Offerly...), (b) a draft order + invoice/checkout link (Magical Make an Offer, BidWise, Noodle, PriceMate, Accord, OfferMe, sf-make-an-offer...), (c) a Cart Transform function that rewrites the line price (CounterOffer, Offer Your Price, Quoffer). Nobody found uses a Discount Function keyed to a code to combine product + shipping + gift effects. Section 1.
3. **The agent protocols carry promotions one way (seller to agent, static) and codes the other way (agent to seller).** Stripe promotion feed, ACP Promotions API (merged Mar 2026), ACP/UCP discount extensions, Google Direct Offers. None has an offer/counter-offer message. The nearest thing in a spec is ACP's **Intent Traces** RFC (agent tells the merchant *why* it cancelled: `price_sensitivity`, `shipping_cost`, `comparison`, with `competitor_price` metadata), which says it "lays the groundwork for merchants to transition from probabilistic retargeting (guessing) to deterministic negotiation (bidding)" and that "A subsequent RFC MAY define Reconsideration Offers". Section 2.
4. **Academic evidence says naive LLM sellers are exploitable and that agent-to-agent bargaining produces real money losses,** which supports "limits in code, never in a prompt" and argues for one-shot quotes with rate limits instead of multi-round haggling. Section 2.9.

**Reading of Flux's design (`inferred`):**

- It is idea A (code as offer token) + idea B(v) (one cross-store connector the buyer already has) and nothing else. Discovery is entirely "the buyer installed/opened the Flux app in ChatGPT or added the Flux MCP to Claude". There is no in-store discovery for an agent that arrives at the store through Shopify's own UCP tools.
- Anti-probing choices worth copying: no counter-offer from the seller in the agent channel (accept-with-quote or decline only), 5 quotes per day per identity, 20-minute quote hold, 1-hour code, identity required, double confirmation, opaque claim URL instead of a raw code in the transcript.
- Gaps OfferAd could occupy: (1) non-price concessions (shipping speed, returns, gift, bundle, next-order credit) - Flux codes are product-level percentage only and explicitly do not combine with shipping discounts; (2) competing-offer link verification - absent; (3) asking the agent for the buyer's priority - Flux takes a budget only; (4) meeting the agent inside the store's own surface (WebMCP tool, storefront text, code menu) so no pre-installed connector is needed; (5) anonymous agents - Flux requires account sign-in, which acting agents (Muse, Dots, Grok Bot) may not be able to complete.
- Risk for OfferAd: Flux already has the Shopify listing, a ChatGPT app, pricing with 5% take rate, and a UK founder shipping fast (four releases in four months). Its traction looks small: 2 reviews, homepage counters show "0+" in static HTML (values load client-side, not verified).

### 1.7 Magical Make an Offer - mechanism from its help centre

- FAQ (https://www.magicalapps.com/frequently-asked-questions-magical-make-an-offer-app/, last updated 8 Oct 2025): "for product offers, only the associated product will show in the checkout. If there are multiple offers on different products, the customer will be sent multiple checkout links." and "If the customer has not checked out yet, you can cancel the accepted offer by deleting the draft order that was created." `primary_source_read`. So: accepted offer -> draft order -> emailed checkout (invoice) link. One draft order per product offer; "order offers" cover a whole cart.
- "How long do counter-offered customers have to wait if they do not want to accept the counter and instead want to make a brand new offer? 24 hours." (same page). That is their anti-probing control: a 24-hour lockout after a counter.
- Counter offers can be marked "Final or Open".

### 2.2 ACP (OpenAI/Stripe Agentic Commerce Protocol): promotions in, intent out, no negotiation

All `primary_source_read` from github.com/agentic-commerce-protocol/agentic-commerce-protocol (RFCs saved under `docs/r6/acp/`):

- **Discount Extension RFC** (`rfcs/rfc.discount_extension.md`, "Status: Draft, Version: 2026-01-27"): "Provide discount code input via the `discounts.codes` array"; responses carry `applied` and `rejected`; "Out of scope: Discount creation/management APIs, coupon validation rules, loyalty point redemption." Same shape as UCP's discount extension, so idea A's code-as-token works on ACP surfaces too.
- **Promotions API** (issue #191 "[SEP] Promotions API", authors "Aravind Rao, Rahul Bansal" of OpenAI, 24 Mar 2026; PR #192 merged): "adds a feed-scoped promotions subresource ... that allows a seller to push promotions". "The API is intended for pre-checkout catalog synchronization rather than transaction-time discount application." Benefits: `amount_off`, `percent_off`, `free_shipping`. Static, not per-buyer.
- **Intent Traces RFC** (`rfcs/rfc.intent_traces.md`, "Status: Proposal, Version: 2025-12-16", PR #54 by 0xtotaylor = Tomas Taylor, merged): the agent may attach to `POST /checkout_sessions/{id}/cancel` an `intent_trace` with `reason_code` in {`price_sensitivity`, `shipping_cost`, `shipping_speed`, `product_fit`, `trust_security`, `returns_policy`, `payment_options`, `comparison`, `timing_deferred`, `other`}, a `trace_summary`, and flat `metadata`. The spec's own example: `"trace_summary": "User verified product fit but found a similar SKU on Amazon for $15 less.", "metadata": {"max_budget": 8500, "competitor_source": "amazon_prime", "competitor_price": 8499}`. Key sentences: "This specification lays the groundwork for merchants to transition from probabilistic retargeting (guessing) to deterministic negotiation (bidding)." "Automated routing: Merchants can trigger different workflows per reason (e.g., `shipping_cost` -> offer free shipping promo code)." "A subsequent RFC MAY define **Reconsideration Offers** keyed to specific reason codes." It is write-only and only fires at cancel. This is the closest thing in any shipped spec text to OfferAd steps (2) and (3): the buyer agent telling the seller its priority and a competitor price. No "Reconsideration Offers" RFC exists in the repo's `rfcs/` folder as of 13 Oct 2026.
- **Sale Extension** (issue #122 / PR #123, Dean Harel of Nekuda, 9 Feb 2026, open): sale name, compare-at price, window, and `discount_eligible` per line item so agents know which items take codes.
- **Suggested Pricing on Checkout Create** (issue #197 / PR #201, lhwa, Mar 2026): agent sends `suggested_price {amount, source, observed_at}`; "the seller SHOULD verify the source and check whether the price was offered within its acceptable time window. If verified, the seller SHOULD honor the suggested price." This is price-source verification inside one seller's own catalog; a cousin of competitor-link verification.
- **Time-bound offer expiry** (issue #164 / PR #165, Kixo, Feb 2026, open): `valid_until` on line items, `offer_expired` error.

### 2.9 Google automated discounts: the first-party precedent for "ad click carries a private price that really applies in Shopify checkout"

This is the closest existing mechanism to idea A, and it is run by Google with Shopify's cooperation. All `primary_source_read` from support.google.com/merchants:

- About (answer 15010391): "Only customers who click your Shopping ads will see the optimized prices on your product pages and during checkout." "You set minimum prices or maximum discounts of at least 5% below a product's current price ... - Custom stores (answer 16961497, "Step 5 of 5: Set up discounted prices in your online store"): the price travels in a Google-signed JWT in the URL: "Decode the Base64URL encoded token, which is passed in a pv2 URL request parameter". Payload fields: "exp - Expiration time ... If the token is expired, it must be rejected. m - Merchant ID. If the merchant ID doesn't match, the token must be rejected. o - Offer ID, used to check if the product page matches the product or a valid variant ... p - Price from automated discounts. pp - Prior price". Signature algorithm ES256. "Discounted prices must show ... On product landing pages for at least 30 minutes, even if customers revisit a product page and the JWT is no longer in the URL. In the cart and checkout process for at least 48 hours."
- Shopify (answer 16565024, "Set up automated discounts on the Google & YouTube app on Shopify"): "Shopify automatically applies discounts to eligible carts ... Floor is a variant metafield: `metafields.mm-google-shopping.auto_pricing_min_price` ("Auto pricing minimum price is the minimum sale price attribute that can be set by automated discounts. Only products with a minimum price will be discounted."). A theme app block ("Automated Discounts Price Block") shows the struck-through price.
- Reading (`inferred`): on Shopify even Google implements a per-click private price as an app that writes auto-generated discount codes plus a theme block, with the merchant's floor held in a metafield. That is idea A, already blessed. The signed-token design (expiry, merchant id, offer id, price, reject on any mismatch) is a ready template for an OfferAd offer token.

**Floor discovery by repeated bids (the weakness named in the task).** I found no paper that measures floor extraction by bisection against a rule-based seller, but the mechanism is arithmetic: any seller that answers accept/decline (or counters) deterministically as a function of the offered price leaks the threshold in about log2(range/step) queries. What deployed products do about it (all `primary_source_read`): Flux: "quotes_per_day: 5", no counter-offer in the agent channel, identity-bound sessions, and "it doesn't rush to your floor either"; Magical Make an Offer: 24-hour wait before a new offer after a counter; ACP Intent Traces RFC: "Merchants MAY additionally ignore or deprioritize traces from sessions exhibiting suspicious patterns (e.g., rapid create-cancel cycles)"; Fasel: "the agent counters over 4-6 rounds". `inferred` countermeasures for OfferAd: accept threshold above the true floor and randomised per identity/day; a small budget of quotes per buyer identity, per product and per IP/agent profile; make the answer depend on verified evidence (a competitor link) and not on the bid alone; never return "your offer was X below what we accept".

## 3. Price-match verification: how it is done today, and how it is abused

### 3.1 Retailer policies (the rules a verifier has to encode)

- **Target** help page (https://help.target.com/help/subcategoryarticle?childcat=Price+Match+Guarantee&parentcat=Policies+%26+Guidelines, read 13 Oct 2026): "Have the current price you want to match ready ... Screenshots or pictures cannot be accepted." "It must be an identical item, brand name, size, weight, color, quantity and model number". Not matched if "The item is on clearance, closeout, liquidation, refurbished or is a typographical error" or when combined with certain coupons. `primary_source_read`. (The competitor list is on a separate policy page I could not fetch.)
- **Newegg** (https://kb.newegg.com/knowledge-base/price-match-guarantee/): now matches only its own price drops within 7 days. "The lower price must be for the exact same item - same model number, item number, and specifications - and is subject to verification." "The item is sold and shipped by Newegg - not a Marketplace or third-party seller." "The item is in stock, and the lower price is active and valid at the time of your request." Excluded: "Prices on external competitor sites (Amazon, Best Buy, Walmart, Target, etc.)", coupon/rebate/gift-card offers, bundles, clearance, open box, "Prices resulting from a typographical error", limited quantities, holiday event prices. `primary_source_read`. Note the direction of travel: a large electronics retailer has stopped matching competitors at all.
- **Walmart 2014** (PCWorld, Ian Paul, 20 Nov 2014, https://www.pcworld.com/article/436480/walmart-closes-price-match-loophole-after-scammers-snag-90-playstation-4s.html): scammers created third-party Amazon listings for a PS4 at about $90, took a screenshot "before Amazon pulled it", and had stores match it. Walmart then limited matching to Walmart.com and about 30 named online retailers and said it won't honor prices from "marketplace vendors, third-party sellers, auction sites or sites requiring memberships", adding "We can't tolerate fraud or attempts to trick our cashiers." `secondary_source` (read through a fetch summary).
- Best Buy, Home Depot, Lowe's, B&H and BBQGuys policy pages returned 403 or a geo page to my fetches. `could not verify` their wording. A 2007 GERAD working paper (G-2007-97) is reported to find that all top-20 US consumer-electronics retailers offering price-match guarantees required verification of availability at the competitor (`secondary_source`, search summary only).

The common rule set, stated as checks a program can run (`inferred` from the policies above):
1. Identical item: brand + model/MPN/GTIN + variant (size, colour, quantity, condition = new).
2. Seller is on an allow-list and is the first-party seller, not a marketplace third party.
3. Price is live now (fetched by the verifier, not a screenshot), in stock, shippable to the buyer's region.
4. Compare like with like: exclude member-only prices, coupons, bundles, gift-card promos, clearance/open-box/refurbished, obvious pricing errors, limited-quantity doorbusters.
5. Compare landed cost: item + shipping + (optionally) tax and return terms.
6. One match per customer/item/period.

### 3.2 Tools

- **Customer-facing price-match claim apps on Shopify: effectively none with automatic verification.** App Store searches for "price match", "price match guarantee", "price beat", "lowest price guarantee", "price promise", "found a lower price", "price match request", "competitor price verification" returned bundle apps, EU guarantee-label apps and competitor trackers. The only shopper-facing price-match app is Smart Price Match Popup (ShopFox, launched 7 Oct 2020, 1 review at 1.0), which does no verification: it shows a popup when the visitor highlights the product title and lets the merchant "ask customers to call/email you, or show a coupon code". `primary_source_read` (search frames and listing). This is an open niche.
- **Merchant-side competitor price trackers** (the verification technology exists, pointed the other way):
  - Prisync (https://prisync.com/features/product-matching/; Shopify app since 16 Jun 2015, 4.9 from 242 reviews, $49 to $399/month): "Prisync offers an automated product matching service by scraping the web and finding exact matches of your products based on GTIN / UPC / EAN barcodes you provide." "Hybrid plan users can add competitor URLs manually to their dashboards alongside automated matches." `primary_source_read`
  - PriceOtus ($0 to $199/month, works with "Amazon, direct competitor URLs, eBay, Google Shopping, Walmart"), Price Parrot ($49 to $249/month, "Automatically find and match competitor products using advanced matching logic", API access). `primary_source_read` of listings.
  - "Price Engine" (identifier-first matching with confidence scores, per a search summary) is now "not currently available on the Shopify App Store". `primary_source_read` for the delisting.
- **Structured data a verifier can read from a competitor page** (Google Search Central, https://developers.google.com/search/docs/appearance/structured-data/merchant-listing): Product markup carries `sku`, `gtin14`/`gtin`, `mpn`, `brand`, and `offers` with `price`, `priceCurrency`, `priceValidUntil`, `itemCondition`, `availability`, `url`, `shippingDetails` (rate, destination, delivery time) and `hasMerchantReturnPolicy` (`merchantReturnDays`, `returnFees`). `primary_source_read`. That is enough to compare price, condition, stock, shipping cost, delivery time and return window, which is exactly the set of dimensions OfferAd wants to trade on.
- **What a Shopify competitor exposes** (`tested_live`, read-only GETs on allbirds.com, 13 Oct 2026): `GET /products.json?limit=1` returns per-variant `price`, `compare_at_price`, `available`, `sku`, `id`, `grams`, but no barcode/GTIN field. The corresponding product page had zero `application/ld+json` blocks (headless storefront), so JSON-LD cannot be assumed. Shopify's UCP `lookup_catalog` accepts only Shopify GIDs ("Product IDs (gid://shopify/Product/...)", "Variant IDs (gid://shopify/ProductVariant/...)" in the live tool description saved in `docs/tools-list.json`), not URLs or GTINs. So for Shopify-hosted competitors the reliable path is: product URL -> `/products/<handle>.js` or `.json` -> variant price and availability, with item identity matched on SKU/title/brand/options, not GTIN.
- **In the agent protocols:** ACP's Intent Traces example carries `competitor_source` and `competitor_price` as unverified metadata (2.2). ACP issue #197 has the seller verify a price `source` + `observed_at` it recognises. Nothing standardises third-party competitor verification.

### 3.3 Abuse patterns (known, with source) and agent-era variants (inferred)

Known:
- Fake third-party marketplace listing + screenshot (Walmart PS4, 2014). `secondary_source`
- Doctored or stale screenshots: Target's rule "Screenshots or pictures cannot be accepted." `primary_source_read`
- Non-identical item passed off as identical (different model number/bundle/refurb): the "identical item" clauses. `primary_source_read`
- Out-of-stock or limited-quantity bait prices: Newegg's exclusions. `primary_source_read`
- Member-only, coupon, gift-card and bundle prices: Newegg/Target exclusions. `primary_source_read`
- Pricing errors: "typographical error" exclusions. `primary_source_read`
- Discount codes leaking to coupon sites: ChatCast's agent terms prohibit sharing codes on "public coupon aggregation websites"; Stabile admits a minted code "isn't bound to the customer it was issued to"; Fasel sells "no coupon leakage" as a feature. `primary_source_read`

Agent-era variants (`inferred`):
- An agent (or a script posing as one) spins up a throwaway Shopify store, lists the product at a low price, and submits that URL. Counter: domain allow-list or reputation (age, order history signals are not public, so prefer merchant-curated competitor lists), marketplace exclusion, and price sanity bands.
- Cloaking: the competitor page shows a low price to the verifier's user agent or region and a normal price to others. Counter: fetch from the buyer's region; cross-check HTML, JSON-LD and any feed; record evidence.
- SSRF and prompt injection against the verifier, since the seller agent fetches a buyer-supplied URL. Counter: fetch in an isolated worker, no credentials, block private IP ranges, parse with code not with an LLM, never feed page text into the model that decides. UCP #384 flags the same class: "Security - SSRF via offer_discovery endpoint".
- Floor probing through price-match: submit successively lower competitor links to map how far the store will go. Counter: cap the concession at a merchant-set match floor regardless of evidence; rate-limit claims per identity.
- Variant mismatch that a human would catch and a GTIN-less matcher will not (size, pack count). Counter: require variant-level identity; when unsure, answer with a non-price concession instead of a price match.
- Collusion among sellers through automated matching is a competition-law risk the merchant carries; not researched here.

## 5. What the prior art says about ideas A to F

- **A (offer token = single-use code).** Validated five times over: Flux, I Want That, Stabile, ChatCast, and Google's own automated discounts on Shopify all end in a generated Shopify discount code. Honest limits seen in the wild: the code is not bound to the buyer (Stabile: "behaves like any other single-use discount code"); Flux scopes to one product and refuses to stack with shipping/order discounts; expiry ranges 60 to 90 minutes (Flux profile, I Want That) up to 72h. Nobody uses a Discount Function to bundle product + shipping + gift under one code, so that part of A is new and unproven. UCP PR #578 (`gift_line_item_id`) shows the spec side expects gifts to be expressed as discounts on a line.
- **B(i) (extra WebMCP tool from a theme app embed).** StoreKnows (launched 28 Sep 2026) "supplies read-only product tools on supported theme-based Shopify stores" through an app embed for "browsers that can use website tools", so App Store review allows app-registered storefront tools (`inferred` that these are WebMCP). I Want That says its UCP-namespaced capability "has to be delivered as a theme extension" on Shopify.
- **B(ii)/(iv) (text, metadata, llms.txt).** I Want That: "adding some meta data into the shop storefront the agent could read and then direct them to the api". ChatCast: per-store `llm.txt` and `start.md`. Stabile: holds the "Edit ... Legal policies" scope. Shopify's own free "Shopify Knowledge Base" app (launched 16 May 2025, 3.5 from 29 reviews) lets a merchant "Create custom FAQs to address a wider array of buyer questions" that "AI shopping agents use to answer questions about your store"; it stores them with the "Edit custom data: Metaobjects" scope. That is the sanctioned channel for B(ii). Whether a third-party app can write those FAQ entries is `could not verify`. Risk from 2.11: frontier agents ignore instruction-like text; Stabile could not tie any agent read of its public data to any order.
- **B(iii) (automatic discount title).** No one found using it as a signalling channel. New.
- **B(v) (cross-store connector in agent directories).** Flux and Stabile both have ChatGPT apps; Stabile's directory listing took effect 25 Aug 2026; Claude accepts a remote MCP "by URL, with no directory approval required" (Stabile). Flux adds cross-store discovery so the connector is useful before the buyer has picked a store. This is the only discovery route with demonstrated end-to-end orders, and the volumes are tiny.
- **C (offer menu carried by codes).** Stripe's promotion feed and ACP's Promotions API are the platform version (static promotions with codes the agent can apply). Nobody uses rejection messages as a guidance channel.
- **D (eligibility claims).** UCP PR #264 "attestation extension for eligibility claims" (closed/merged, Mar 2026) and issue #287 "Wallet Attestation - Identity Mechanism + Eligibility Extension" exist; I did not read them. No product found using claims for offers.
- **E (custom UCP extension).** Works where you control the profile (Shopware `com.shopware.quote` and `com.a2cn.negotiation-mandate` live on sw-ag.dev; Flux on its own domain, both `tested_live`). On Shopify the store profile is closed to apps (three independent confirmations: the brief's allbirds check, Stabile's four stores, the Flux demo store; plus Chris Daly's "Shopify blocked it"). And even where published, "A compatible buyer agent would still need to advertise support" (Arjun Garg).
- **F (draft orders / invoice URLs).** This is the majority mechanism among human-facing offer apps (Magical, BidWise, Noodle, PriceMate, Accord, OfferMe, Haggler...), because a draft order can carry any price, shipping line and gift. Its weakness for agents: the checkout link is delivered by email or shown on-site; none of these apps returns it to an agent. `inferred`: a seller endpoint could return the draft-order invoice URL directly as the `continue_url`-style handoff.

New leads surfaced by this research (`inferred`, for the synthesis step):
1. **Verified price-match as the wedge.** No Shopify app verifies a competitor link automatically, even for humans. A "bring a link, we check it, you get a matched price or a better non-price term" feature has value on day one without any agent, and the same endpoint serves agents later.
2. **Position OfferAd as a UCP "Provider" (issue #384).** If the Provider participant lands, an offer network linked by the buyer on the platform side is exactly what the proposal calls `offer_discovery`, and it sits in the platform's profile, which sidesteps Shopify's closed business profile.
3. **Join the standards thread now.** #502, #738, #845, #929 are active this week; the people writing them (Intuit, Google London, Shopware, I Want That, Stabile, Facet) are reachable in public. Non-price terms are explicitly unowned.
4. **Personal Agent Protocol v0.1** (due later in October) starts with website discovery and allows routing to "the company's agent". Read it on release for a sanctioned way to advertise a store-side negotiating agent to Muse.
5. **Copy Google's token design** for the offer token: signed, short expiry, merchant id, offer/variant id, price or term, reject on any mismatch.
6. **One-shot quotes, not chat.** Flux, UCP #929 and the first-proposal-bias result all point to accept/decline/quote in a single response with tight rate limits.

1. None is merged.
2. Brief item 6 (extensions need both profiles; Shopify generates the store's profile): confirmed again on fluxdemo.myshopify.com (ten capability keys, all `dev.ucp.*`/`dev.shopify.*`, including `dev.ucp.shopping.permalink` and `dev.ucp.common.identity_linking`), by Stabile on four stores, and by a founder who says Shopify blocked his namespaced capability. Addition: vendors publish their own UCP profile on their own domain instead (Flux), and UCP #384 would add a Provider slot on the platform side.
3. Brief item 11 can be upgraded from "reported by press": the Personal Agent Protocol post and Google's Direct Offers pages are now read at the primary source (2.4, 2.6). 6. Idea E has live examples outside Shopify (Shopware demo store publishes `com.shopware.quote` and `com.a2cn.negotiation-mandate`).
